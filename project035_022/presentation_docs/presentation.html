SPEAKER GUIDE & SYSTEM ARCHITECTURE

สรุปโครงงานระบบแจ้งซ่อม IT (IT Helpdesk System)

เอกสารประกอบการพูดนำเสนอหน้าห้อง: Laravel Framework, ฐานข้อมูล MySQL, 3 ฟีเจอร์ใหม่ & แผนผังบทบาท

สถาปัตยกรรม: PHP Laravel Framework (MVC Pattern) ฐานข้อมูล: MySQL 5.7 / 8.0+ (InnoDB utf8mb4) วันที่นำเสนอ: ตุลาคม 2026

📌 1. ภาพรวมระบบเดิม และที่มาของการพัฒนาต่อยอด

ระบบเดิม: เป็นระบบรับเรื่องแจ้งซ่อม IT พื้นฐาน แต่พบข้อจำกัดสำคัญในชีวิตจริง 3 ประการ: ไม่มีรูปภาพประกอบ (ช่างต้องเดาอาการ), ไม่มีการจัดลำดับความเร่งด่วน (เคสวิกฤติตกหล่น), และ ไม่มีการบันทึกข้อความช่าง (ผู้ใช้ไม่ทราบความคืบหน้า)

⭐ 2. สรุป 3 ฟีเจอร์สำคัญที่พัฒนาเพิ่มเติม (Core Enhancements)

ฟีเจอร์ที่ 1: ระบบแนบรูปถ่ายหลักฐานปัญหา (Issue Attachment & Photo Upload) Visual Evidence

ผู้ใช้สามารถแนบรูปถ่ายหน้าจอ Error หรืออุปกรณ์ชำรุด (ไม่เกิน 2MB) โดยรูปภาพจะถูกจัดเก็บลง Storage ของ Laravel และแสดงทั้งในหน้า Dashboard ช่าง และหน้าติดตามสถานะของผู้ใช้

จุดแก้โค้ด: ตาราง tickets เพิ่มฟิลด์ image_path, TicketController.php ใช้คำสั่ง store('tickets', 'public')

ฟีเจอร์ที่ 2: ระดับความเร่งด่วน & หมวดหมู่อุปกรณ์ พร้อมระบบคัดกรองงาน (Priority, Category & Filter) SLA & Prioritization

ระบุความด่วน 4 ระดับ (ด่วนที่สุด, เร่งด่วน, ปานกลาง, ต่ำ) และแบ่ง 5 หมวดหมู่ พร้อมแผง Filter และจัดเรียงให้เคส Urgent ลอยขึ้นมาแสดงบนสุดอัตโนมัติ ช่วยช่างจัดคิวงานตามหลัก SLA

จุดแก้โค้ด: ตาราง tickets เพิ่ม priority, category, AdminTicketController.php กรองด้วย Eloquent $query->where(...)

ฟีเจอร์ที่ 3: ระบบบันทึกข้อความช่าง & ไทม์ไลน์ติดตามผล (Technician Action Notes & Status Timeline) Transparency & History

เพิ่มช่องบันทึกการซ่อม (Admin Notes) ให้ช่างพิมพ์สรุปสิ่งที่ทำ และประทับเวลาปิดงาน (resolved_at) อัตโนมัติ โดยส่งไปแสดงในหน้าติดตามสถานะของผู้ใช้ (Track) แบบ Real-time พร้อมแถบ Progress Bar

จุดแก้โค้ด: ตาราง tickets เพิ่ม admin_notes, resolved_at, track.blade.php แสดง Progress Timeline และกล่องข้อความช่าง

👥 3. การจำแนกบทบาทในระบบ: ส่วนผู้ใช้ vs ส่วนเจ้าหน้าที่ vs จุดเชื่อมต่อ

👤 1. ส่วนของผู้ใช้งานทั่วไป (User / Public Area) ไม่ต้องล็อกอิน (Zero-Friction)
สิ่งที่ผู้ใช้ทำได้:
  • กรอกแบบฟอร์มแจ้งซ่อม (ชื่อ, แผนก, รายละเอียด)
  • ระบุระดับความด่วน และเลือกหมวดหมู่อุปกรณ์
  • แนบรูปถ่ายหน้าจอ error หรืออุปกรณ์ที่ชำรุด
  • ได้รับรหัสเฉพาะ Ticket Number หลังส่งคำขอ
ไฟล์และโค้ดที่รับผิดชอบ:
  • TicketController.php (index, create, store, success)
  • resources/views/tickets/index.blade.php (หน้าแรก)
  • resources/views/tickets/create.blade.php (ฟอร์มแจ้ง)
  • resources/views/tickets/success.blade.php (หน้ารับรหัส)
🛠️ 2. ส่วนของเจ้าหน้าที่ IT / ผู้ดูแลระบบ (Admin & Staff Area) ระบบล็อกอิน (Auth Middleware)
สิ่งที่เจ้าหน้าที่ทำได้:
  • ดูแดชบอร์ดภาพรวม และตัวนับเคสค้างด่วนที่สุด
  • ใช้ Filter คัดแยกงานตามความด่วน / หมวดหมู่
  • เปิดดูรูปภาพหลักฐานเพื่อเตรียมอะไหล่ก่อนไปซ่อม
  • มอบหมายช่างผู้รับผิดชอบ และเปลี่ยนสถานะงาน
  • พิมพ์บันทึกวิธีแก้ปัญหา (Admin Notes) และปิดงาน
ไฟล์และโค้ดที่รับผิดชอบ:
  • AuthController.php (login, logout)
  • AdminTicketController.php (dashboard, show, update)
  • resources/views/auth/login.blade.php (หน้าล็อกอิน)
  • resources/views/admin/dashboard.blade.php (แดชบอร์ด)
  • resources/views/admin/show.blade.php (ตรวจเคส/บันทึก)
🤝 3. ส่วนที่นำทั้ง 2 ส่วนมาร่วมเข้าด้วยกัน (Shared Integration & Bridge) จุดเชื่อมต่อข้อมูลระหว่างผู้ใช้กับช่าง
จุดเชื่อมต่อ กลไกในระบบ บทบาทการทำงานร่วมกัน
1. รหัสติดตามตั๋ว (Ticket ID) ticket_number (เช่น TK-202610-A1B2) เป็น "กุญแจเชื่อมต่อ" ผู้ใช้ถือไว้ค้นหา ช่างใช้เป็นรหัสอ้างอิงในการลงบันทึกงาน
2. หน้าติดตามสถานะ (Track System) tickets/track.blade.php & TicketController@track ผู้ใช้กรอกรหัสตั๋ว แล้วหน้าจอจะดึงข้อความที่ช่างบันทึกไว้ในหลังบ้าน (Admin Notes) และ Progress Bar มาแสดงให้ผู้ใช้เห็นทันที
3. ฐานข้อมูลและโมเดลร่วม ตาราง tickets & โมเดล Ticket.php เป็นตัวกลางเก็บข้อมูลฝั่งผู้ใช้ (ปัญหา, รูปภาพ) และข้อมูลฝั่งช่าง (สถานะ, วิธีแก้ปัญหา, ช่างผู้รับผิดชอบ, เวลาปิดงาน)
4. เมนูบาร์หลัก (Layout Header) layouts/app.blade.php เมนูบาร์ร่วม ตรวจสิทธิ์ด้วย @auth ถ้าเป็นช่างจะเห็นปุ่มเข้าหลังบ้าน ถ้าเป็นคนทั่วไปจะเห็นปุ่มแจ้งซ่อม

🗄️ 4. โครงสร้างฐานข้อมูล MySQL (MySQL Database & Architecture)

การเชื่อมต่อ MySQL: Laravel เชื่อมต่อกับ MySQL ผ่านไฟล์ .env โดยใช้พารามิเตอร์ DB_CONNECTION=mysql, DB_HOST=127.0.0.1, DB_PORT=3306, DB_DATABASE=it_helpdesk ซึ่งรองรับทั้งบน XAMPP, Laragon, และ MySQL Server ทั่วไป พร้อมไฟล์ SQL สำเร็จรูป database/it_helpdesk.sql สำหรับ Import เข้าใช้งานได้ทันที

📊 4.1 แผนผังตารางในฐานข้อมูล MySQL (Data Dictionary)

📋 ตาราง users (จัดเก็บข้อมูลเจ้าหน้าที่ IT และผู้ดูแลระบบ)
ชื่อฟิลด์ (Field) ชนิดข้อมูล (Type) คีย์ (Key) คำอธิบาย (Description)
id BIGINT UNSIGNED PK (AI) รหัสประจำตัวผู้ใช้งาน (Primary Key)
name VARCHAR(255) - ชื่อ-นามสกุลของเจ้าหน้าที่ IT
email VARCHAR(255) UNIQUE อีเมลสำหรับเข้าสู่ระบบ
password VARCHAR(255) - รหัสผ่านที่เข้ารหัสด้วย Bcrypt Hash ปลอดภัย 100%
role VARCHAR(50) - ระดับสิทธิ์: admin, staff (default: 'staff')
🎫 ตาราง tickets (จัดเก็บข้อมูลใบแจ้งซ่อม IT พร้อมรองรับ 3 ฟีเจอร์ใหม่)
ชื่อฟิลด์ (Field) ชนิดข้อมูล (Type) คีย์ (Key) คำอธิบาย (Description)
id BIGINT UNSIGNED PK (AI) รหัสไอดีรายการแจ้งซ่อม (Primary Key)
ticket_number VARCHAR(50) UNIQUE, IDX รหัสติดตามงานเฉพาะตัว เช่น TK-202610-0001
title VARCHAR(255) - หัวข้อปัญหาที่ต้องการแจ้งซ่อม
description TEXT - รายละเอียดอาการเสียหรือข้อความ Error ที่พบ
requester_name VARCHAR(150) - ชื่อผู้แจ้งซ่อม (ฝั่งผู้ใช้ทั่วไป)
requester_email VARCHAR(150) - อีเมลสำหรับแจ้งเตือนและค้นหา
status ENUM(...) INDEX สถานะ: pending, in_progress, resolved, cancelled
image_path ⭐ VARCHAR(255) - ฟีเจอร์ 1: ที่อยู่ไฟล์ภาพหลักฐานใน Storage
category ⭐ ENUM(...) INDEX ฟีเจอร์ 2: hardware, software, network, printer, other
priority ⭐ ENUM(...) INDEX ฟีเจอร์ 2: urgent, high, medium, low
admin_notes ⭐ TEXT - ฟีเจอร์ 3: บันทึกวิธีแก้ปัญหาหรือคำแนะนำจากช่าง IT
assigned_to BIGINT UNSIGNED FK Foreign Key เชื่อมกับ users.id (ช่างผู้รับผิดชอบงาน)
resolved_at ⭐ TIMESTAMP - ฟีเจอร์ 3: วัน-เวลาที่ดำเนินการซ่อมเสร็จสิ้น (ปิดงาน)

🔄 5.1 วงจรการทำงานของ Laravel (Request Lifecycle)

1 เบราว์เซอร์ส่ง HTTP Request
ผู้ใช้กดส่งฟอร์มแจ้งซ่อม POST /tickets หรือเข้าดูหน้า Dashboard GET /admin/dashboard
2 Routing & Middleware ตรวจสอบ
ตรวจสอบ URL จาก routes/web.php, ตรวจสอบ @csrf และสิทธิ์ล็อกอิน auth
3 Controller ทำการ Validation
ตรวจสอบไฟล์ภาพไม่เกิน 2MB, บันทึกลง Storage, และสุ่มสร้างรหัส Ticket ID
4 Eloquent ORM บันทึกลง MySQL
ส่งคำสั่ง Insert/Select ไปยังฐานข้อมูล MySQL แบบป้องกัน SQL Injection 100%

💡 7. แนวทางเตรียมตอบคำถามอาจารย์ (Anticipated Q&A)

❓ ถาม: ทำไมใน MySQL ถึงเลือกใช้ ENUM กับฟิลด์ status, priority และ category?
ตอบ: เพราะข้อมูลเหล่านี้มีค่าที่แน่นอนและจำกัด (Fixed Set) การใช้ ENUM ใน MySQL ช่วยประหยัดพื้นที่จัดเก็บ ป้องกันการกรอกข้อมูลผิดพลาด และทำงานร่วมกับ Eloquent Query ได้อย่างรวดเร็วมากครับ
❓ ถาม: หากเปิดใช้กับ XAMPP ต้องทำอย่างไรบ้างในการรันระบบ?
ตอบ: เปิดโปรแกรม XAMPP Control Panel กดปุ่ม Start ที่ MySQL จากนั้นเข้า http://localhost/phpmyadmin แล้วกด Import ไฟล์ database/it_helpdesk.sql ก็จะได้ฐานข้อมูลพร้อมตารางและข้อมูลจำลองครบถ้วน จากนั้นสั่งรัน php artisan serve ก็พร้อมใช้งานได้ทันทีครับ
